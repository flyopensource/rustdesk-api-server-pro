# 设备管理 TODO 与实施计划

更新：2026-09-08。开发阶段按当前模型实现，不做历史数据迁移/旧版本过渡。勾选表示代码与对应本地自测完成，不代表实际部署或联调验收。

## 已确定范围

- Web 设备管理编辑统一设备别名，并选择发布到哪些账号的个人地址簿。
- 实际 RustDesk ID 不变；连接方使用官方原版客户端，配置自己的 ID Server/Key/Relay/API，登录并刷新地址簿后搜索别名、选择设备连接。
- 保留当前官方开源版 hbbs 1.1.16；不做真实 Custom ID 部署、不改 hbbs、不要求重新打包连接方官方客户端。未登录/未同步时不承诺直接输入别名连接。
- 无人值守文件权限属于受管 Android 客户端，使用私有构建开关，与“连接方官方客户端无需重打包”是两件事。
- 每步本地自测后单独提交；官方客户端、真实 API/hbbs 和 Android 主板端到端联调按要求暂缓。

## 第 1 步：设备停用与重新启用

- [x] `device.disabled` 表达管理状态；有签名凭据时同步设置 `device_credential.enabled`。
- [x] 管理员启用/停用接口、Web 确认操作、状态显示与筛选。
- [x] 拒绝已停用设备的注册、签名和普通心跳/信息上报；启用保留组、策略及签名序号。
- [x] 同一事务记录管理员、设备实际 ID、操作和时间；重复状态操作不重复写审计。
- [x] 本地验证权限、重复操作、并发一致性及审计失败回滚。

边界：停用撤销的是管理 API 访问与后续策略获取，不保证中断 hbbs 会话、清除客户端缓存策略或撤销地址簿用户的远程连接能力。普通设备没有签名凭据时也可管理启用/停用。

## 第 2 步：无人值守文件权限

- [x] 私有 Android 构建 `-PmanagedStorage=true` 声明文件权限，本地 release 脚本自动启用；默认构建继续移除权限。
- [x] Android 11+ 用 `Environment.isExternalStorageManager()` 复检；Android 10 使用 legacy storage，旧系统检查读写运行时权限。
- [x] 沿用已校验 Root 执行器和命令超时尝试授权；失败不得上报无人值守 `success`。
- [x] Root 不可用/授权失败时提供手动设置入口，报告 `partial`/`pending_user_action` 和稳定错误码。
- [x] 定期复检并经签名心跳上报 `all_files_access_ready`；服务端持久化，Web 显示权限与上报时间。
- [x] 开放主共享存储且保留路径检查；拦截父目录穿越、越界/悬空符号链接和 `Android` 目录。共享存储根只供浏览，批量文件操作选择具体子目录。
- [x] 关闭无人值守关闭共享存储访问通道，不自动撤销系统权限，以免撤销用户原先的授权。
- [x] 本地 Kotlin 编译、Dart 分析、受管/默认清单检查、独立 Rust 路径测试、心跳持久化及 Web 类型检查。
- [x] ARMv7 Android Rust `cargo ndk check`（`flutter,hwcodec`）通过，不等同于链接和 APK 打包。
- [ ] 完整 Rust 原生 Android 构建及新 APK 验证。
- [ ] 主板自动授权、拒绝授权、Root 不可用、重启/撤销权限后状态测试。
- [ ] Android 11+ 设备验证和远程浏览、上传、下载联调。

已连接主板为 Android 7.1/API 25；本轮没有安装/替换 APK，没有对主板执行授权或远程文件操作。所有文件访问不等于访问系统根目录、其他应用私有数据或绕过 Android 系统隔离。

## 第 3 步：Web 别名与地址簿同步

- [x] `device.alias` 与设备上报字段分离，信息上报不覆盖 Web 名称。
- [x] Web 别名列、搜索、编辑/取消/保存和同步目标多选。
- [x] 管理员按设备数字 ID 更新；支持中文、修剪首尾空白、清空，拒绝控制字符与超过 128 字的名称。
- [x] 只发布到明确选中的账号已有个人地址簿；显示账号和地址簿名，拒绝共享地址簿和停用账号。账号需先登录客户端创建个人地址簿。
- [x] 别名、`peer` 关联和审计在同一事务中保存；按账号/地址簿/实际 ID 唯一索引保证不重复。
- [x] 已有个人条目仅改别名与管理标记，保留密码、标签等；无关条目不改。
- [x] 取消目标时：本功能新建的条目删除；已有个人条目保留当前名字并解除管理，不追溯恢复旧名字。
- [x] 保留官方客户端现有逐条/整本地址簿接口，不增加客户端定制协议；受管名称以 Web 为准，回写旧名称不覆盖，逐条密码/标签更新仍有效。
- [x] 本地测试中文/清空/重复保存、两种读取、账号隔离、旧值回写、并发原子性、取消发布及事务回滚；模拟页面测试覆盖编辑、取消和提交参数。
- [ ] 官方原版客户端登录自己的 API、刷新后看到新别名，记录实际平台与版本。
- [ ] 官方客户端搜索“上海店”，按真实 ID 区分重名，选择设备完成实际连接。
- [ ] 真实设备后续信息上报、客户端缓存刷新、重新登录后的持续正确性验证。

服务端保存成功只表示目标地址簿已更新，不表示官方客户端已经刷新；地址簿发布不是远程会话授权。

## 第 4 步：受限制的单设备删除

- [x] 仅管理员按数字 ID 删除，必须已停用且离线，要求输入完整 RustDesk ID 二次确认。
- [x] 条件删除再次校验状态，事务内清理设备行、凭据和受管地址簿关联。
- [x] 设备分组关联已内置于设备行；删除设备不删除共享设备组和服务器配置，保留已有个人条目并解除管理。
- [x] 保留历史审计和实际 RustDesk ID 快照，新增删除审计，不记录私钥、enrollment key 或签名内容。
- [x] Web 危险操作提示：物理删除不是永久封禁，设备仍可能重新注册，客户端本地缓存不会立即清除。
- [x] 本地测试未授权、正常/在线设备、错误 ID、不存在、重复删除、关联清理和审计失败回滚；模拟页面验证确认输入门槛。
- [ ] 联调确认删除后的再次注册行为与在线状态刷新，不把管理 API 的在线状态当作 hbbs 会话状态。

## 第 6 步：设备组完整策略

- [x] 服务器配置只保留 ID Server、Relay Server 和 Server Key，不再保存固定密码。
- [x] 设备组统一保存服务器配置引用、无人值守、固定密码密文和 Root 执行器。
- [x] 删除单设备服务器配置、单设备无人值守和全局服务器配置入口，以所属组、默认组、无策略顺序整组解析。
- [x] 关闭无人值守时不向客户端下发组固定密码，重新开启后从设备组恢复。
- [x] Web 设备列表只允许调整所属设备组，其他策略和应用结果只读展示。
- [x] Web 将唯一默认开关并入设备组表单，展示直接分组数和默认覆盖数；`auto` Root 执行器明确说明依次探测 `su`、`testsu`。
- [x] 默认关系与设备组同事务保存，新默认组自动替换旧默认组；停用当前默认组时同步清除关系。
- [x] 只有未分组设备使用默认组；已分组但所属组不可用时返回无管理策略并告警。
- [x] 服务端测试覆盖整组解析、默认组回退、密码保留/清除、响应脱敏及关闭无人值守清空下发密码。
- [x] Web 类型检查、生产构建和模拟页面测试。
- [ ] 使用全新策略数据部署，重新创建服务器配置、设备组、固定密码和默认设备组。
- [ ] 真实设备验证切组、默认组回退、服务器重连、无人值守启停、固定密码更新及状态上报。

详细模型与接口见 [设备组策略模型调整方案](device-group-policy-redesign.md)。旧策略数据不迁移、不兼容。
